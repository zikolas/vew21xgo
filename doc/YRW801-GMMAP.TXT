YRW801 GM program -> wave map - TWO INDEPENDENT SWEEPS, MERGED
=========================================================================
probes/VEW2MAP.C on the CF-VEW212, 2026-08-28, vendor DOS stack resident
(OPL4TSR + SCPRODOS /C330 /M388 /I9 + OPL4DRV), card on COR index 26h.
For each program a program change and a note go to the MPU-401 at 330h
and the OPL4's voice registers are read back.  Only the chip's own
registers are examined - no driver is disassembled.

WHY TWO SWEEPS
  The tool reports the lowest keyed voice, so where the renderer LAYERS
  two waves for one program, which one it sees is arbitrary.  Running the
  sweep twice and diffing turns that weakness into information: a cell
  that reads the same both times is a single-layer patch, and a cell that
  differs shows BOTH layers.  A "a/b" entry below means both a and b were
  observed and both are real.

RESULTS
  128 programs, 640 cells, 0 silent probes.
  91 programs identical across both runs - single layer, trustworthy.
  37 programs differ - LAYERED, and the pair names both waves.
  No wave above 383 is ever used, confirming that 384-511 need external
  memory this card does not have.

READING IT
  A number changing across a row is a MULTISAMPLE KEY SPLIT, e.g.
  program 0 walking 300 302 304 306 308 up the keyboard.  Programs
  sharing a sequence draw on the same multisample bank.  Program 62
  resolves to {211,212,213,214,215} layered with {280,282,284,286,288}.

CAVEAT - THE DRUM MAP IS NOT HERE AND IS UNSOLVED.  Channel 10
percussion plays to the end of its sample whatever the note-off says, so
every note reports the same stale voice.  Two attempted fixes made it
worse; see the VEW2MAP.C header before trying again.
